# rona

A video player with mpv as the playback backend and Slint for the UI, written in Rust. Licensed GPL-3.0-or-later. Only Windows has been tested so far. Linux and macOS are planned.

## Build and run

- libmpv is not built from source. On Windows, `cargo xtask fetch-mpv` downloads `libmpv-v0.42.0-x86_64-w64-mingw32-gpl.zip` from the mpv v0.42.0 GitHub release, checks it against the SHA-256 pinned in `xtask/src/mpv.rs` and extracts it to `vendor/mpv/windows-x86_64/`. `vendor/` is gitignored. `build.rs` copies `libmpv-2.dll` next to the exe. On Linux, libmpv comes from the system (`libmpv-dev`).
- `cargo run -- [file paths or http(s) URLs]`. Without an argument the window opens empty. `--version` prints the version, starts mpv to check libmpv loads, and exits. `--new-instance` skips single instance, so a `cargo run` while Rona is open starts its own window instead of handing the files to the open one.
- Judge performance with `cargo run --release`. Debug builds make Slint's text code slow, for example the first open of the tracks menu stalls for about 600 ms in debug and not in release.
- `assets/icon.svg` is the only source for the app icon. The title bar uses `assets/title-icon.svg` instead, a bare play triangle, since the dark tile vanishes on the title bar at 16 px. `build.rs` renders it with `resvg` to raw RGBA at 32 and 256 px for the window and taskbar icon (set through winit in `set_window_icons`). On Windows it also builds a multi-size `.ico` with the `image` crate and embeds it in the exe with `winresource`, which needs the Windows SDK's resource compiler. On Linux it writes `share/applications/rona.desktop` and `share/icons/hicolor/<size>/apps/rona.png` (plus the SVG under `scalable`) next to the binary, laid out so installing is copying `share` into `~/.local` or `/usr`. The window's Wayland app id and X11 class are `rona` to match.
- libmpv is loaded at runtime with `libloading`, so there is no link step. The headers in `vendor/mpv/windows-x86_64/include/mpv/` are the reference for every constant and struct in `src/mpv.rs`.

## Layout

- `src/main.rs`: wiring between mpv and the UI, mpv event handling, UI callbacks, window controls, OSD, download speed polling.
- `src/mpv.rs`: hand-written bindings for the client API, the OpenGL render API and the stream callback API.
- `src/video.rs`: `VideoLayer`. mpv renders into an offscreen buffer, which is copied into the video area every frame. The buffer depends on the Renderer setting, which is only read at startup because switching means rebuilding mpv's video output: a Direct3D 11 texture shared with OpenGL (Windows, `src/video_d3d11.rs`, falls back to OpenGL if unavailable) or an OpenGL renderbuffer. mpv's Vulkan support (`vo=gpu-next`, `gpu-api=vulkan`) belongs to its own video output, which the render API replaces, so it isn't offered here.
- `src/http_cache.rs`: the `rpcache://` protocol that http(s) URLs go through, with a byte cache. A read that fails mid-stream reconnects at once, then after 3, 6 and every 12 s, and only shows the connection banner while playback is buffering. Most failures are the server closing a connection left idle while mpv's buffer was full, so they never show.
- `src/instance.rs`: single instance. The first launch claims a named pipe (`\\.\pipe\rona-<session id>`, created with `FILE_FLAG_FIRST_PIPE_INSTANCE`) on Windows, or `flock`s a lock file and binds a Unix socket in `XDG_RUNTIME_DIR` elsewhere. Both are atomic and released when the process dies, so two launches at once can't both win and a crash leaves nothing stale. Later launches send a length-prefixed message (the Wayland activation token, then the sources, NUL separated, relative paths already made absolute) and exit only once the window replies that its UI thread took it. A hidden window (closing) or no reply within 10 s makes that launch run as its own window, as does any failure to claim or connect. Each connection gets its own thread (and on Windows a fresh pipe instance), so a stuck sender blocks nobody. On Windows the sender calls `AllowSetForegroundWindow` for the running window, since only the process the user just started may take the foreground. winit's `focus_window` does nothing on Wayland, so `src/wayland.rs` calls `xdg_activation_v1.activate` with the sender's `XDG_ACTIVATION_TOKEN` on the window's own connection. The window opens what arrives within 150 ms of the last launch (`opener::queue_arguments`) as one playlist, because Explorer can start one process per selected file. `--new-instance` and `RP_CAPTURE` runs skip all of this. The design follows Tauri's single-instance plugin, except that Tauri's macOS version removes and rebinds its socket without a lock, which can leave two primaries.
- `src/audio_info.rs`: reads local audio files' tags and cover with `lofty` on a background thread, before mpv opens them, so the audio view switches to a file all at once. The playlist read queues the current file, the next 3 and the previous one, and a starting file that isn't cached yet jumps the queue. It reads the same keys the view took from mpv's metadata, and looks for the cover names mpv's `cover-art-auto` uses when there's no embedded one. Covers (JPEG, PNG, WebP) are scaled to at most 640 px and kept decoded for the last 24 files. Behind those full reads, only the title tag of every playlist entry is read (without cover art) and kept for all of them, because mpv only knows a file's title once it has played it. The playlist is read again after each full read and each finished batch of titles. A pre-read cover is drawn by Slint (`has-cover-image`, `cover-image`); mpv's own cover rendering is the fallback for files `lofty` can't read. While a file opens, mpv's title and tags aren't applied (mpv empties them mid-switch); without pre-read info the view switches to mpv's when playback starts.
- `src/media.rs`: what counts as playable. Link parsing, the video and audio extension lists, the Content-Type list that rules a link out, and byte signatures for the first 4 KiB. No UI.
- `src/opener.rs`: every way a file or link gets opened (command line, file dialog, link box, Ctrl+V, drag and drop), the link check before mpv sees a link without a media extension, and the failure screens. `Player.phase` (idle, checking, opening, playing, failed) is set here and in `drain_events`. While something plays, a failed open only shows an OSD message.
- `src/settings.rs`: the settings. `Config` is loaded from `settings.conf` (plain `name = value` lines) in the user config folder (`%APPDATA%\rona` on Windows), written back on every change, and applied to mpv as `set` commands after startup, so an option this mpv build doesn't know only logs a failed command. Only properties whose value changed are sent again. The Slint `Settings` global holds what the dialog shows, and its `changed` callback makes Rust read it all back.
- `src/theme.rs`: theme profiles (Settings > Theme). The values in `ui/theme.slint` are the default theme, read at startup before anything is overridden, so "Default" is not a stored profile and can't be edited or deleted. Each profile is `themes/<name>.conf` in the config folder, `name = value` lines holding only the values that differ from the default, so a property added to `theme.slint` later shows its default in every profile. The chosen profile is `theme` in `settings.conf`, empty for the default. Slint globals can't be looked up by name, so every `Theme` property is listed in the `keys!` table there, and a new one needs a line in it. Values are colors (saved as `#rrggbb` or `#rrggbbaa`), lengths in px and durations in ms. A new profile copies the one shown, profile names are file names, and "Reset this page" reverts the whole profile. A changed value is written 400 ms after the last change, since dragging in the color picker changes it many times a second, and any write still waiting is done before switching, renaming or closing.
- `src/color.rs`: reading and writing color text, behind the Slint `ColorText` global. It takes hex with or without `#` (3, 4, 6 or 8 digits) and CSS `rgb()`, `rgba()`, `hsl()`, `hsla()`, `hsv()` and `hsb()` in comma or space syntax with `/ alpha`, and writes `#rrggbb`, or `#rrggbbaa` when not opaque.
- `src/state.rs`: what Rona remembers on its own rather than what the user chooses: the two volume levels and the window's place and size. It lives in `state.conf` next to `settings.conf`, in the same `name = value` format, so `settings.conf` is only written when a setting changes and can be a read-only file managed by something else. Versions up to 0.1.1 kept these values in `settings.conf`, so that file is read first and `state.conf` wins.
- `src/chapter_skip.rs`: skipping chapters whose titles contain one of the user's names as whole words (Playback settings, empty by default). It reads its settings from the Slint `Settings` global, because `drain_events` runs in a `Send` closure that can't hold `SharedConfig`. It also checks on position updates, since the chapter list is read in the background and can arrive after the chapter is known. Each chapter is checked once per file, so going back to one plays it.
- `src/updater.rs`: checking for and installing updates (Settings > Updates, and a check 5 s after startup unless turned off). It reads `updater/latest.json`, verifies the download with `minisign-verify` against `assets/update-key.pub` (compiled in) before saving it, and only hands it over after the window has closed through the normal close path, so the resume position and settings are saved first: on Windows it starts the NSIS installer with `/P /R`, on Linux it renames the new AppImage over the running one and starts it. Self-update is off in debug builds, without the `self-update` feature, with an empty key file, and on Linux outside an AppImage; the page then points to the download site. `RONA_UPDATE_ENDPOINT` points it at a test manifest and allows installing from a debug build. `cargo-packager-updater` was not used because it exits the process itself when the installer starts, skipping our saves, and brings a second HTTP client.
- `xtask/`: release tooling, run as `cargo xtask <command>` and never shipped (see Releases).
- `src/volume.rs`: the last volume set in the player, kept as `video-volume` and `audio-volume` in `state.conf`. The level for the file's kind is set in the `on_load` hook, so it applies before any sound. The file name decides the kind there, and it's corrected at playback start when the tracks say otherwise. Changes are saved 1 s after the last one, and on close. Resume leaves `volume` out of what it saves per file, so it can't override this.
- `src/shortcuts.rs`: the rebindable keys. The window's key handler passes every key to `Player.key-pressed`, which looks it up here. Letters are stored lowercase so Shift doesn't change the match. Shift with the seek keys uses the long seek step.
- `src/recorder.rs`: recording. Start and Stop only remember playback positions. Copy mode then writes that range with mpv's `dump-cache` (lossless, same container as the source, subtitles stay a separate track), one part at a time, and raises `demuxer-max-back-bytes` while recording so the range is still buffered. `stream-record` is not used because it starts at mpv's read-ahead point, which can be minutes past what is on screen. Re-encode mode encodes the range in a second, hidden mpv instance in encoding mode (`o`, `ovc`, `oac`, `start`, `end`), which mpv only finishes writing when that instance is destroyed.
- `ui/app.slint`: root window. `ui/state.slint` holds the globals (`Player`, `WindowControls`, `Panels`) and the structs passed from Rust. Rust reaches the UI through `app.global::<Player>()` and friends, not through window properties.
- `ui/theme.slint` has colors, bar heights and the shared transition timings, as the default theme. Its properties are `in-out` so `src/theme.rs` can override them. Every hover, press and focus change animates (`animate background`, `border-color` and so on) with `Theme.hover-duration`, and every popup, menu and dialog fades in and out with `Theme.fade-duration`. A dialog behind an `if` is kept while a fade value is above 0 (`link-fade`, `settings-fade` in `app.slint`), since an `if` alone destroys it at once. `ui/components/` has small shared pieces, with our own form controls in `form.slint` because Slint's standard widgets look different per platform. `ColorField` there is the full color picker (a swatch opening a saturation and brightness square with hue and alpha sliders, next to a field that takes pasted colors in any format `src/color.rs` reads, converted when focus leaves). `ColorChoice` only picks from a fixed row of swatches. Anything clickable uses `Clickable` from `clickable.slint` (a `TouchArea` with the pointer cursor) instead of a bare `TouchArea`, which stays only for backdrops, hover detection and resize edges.
- `TextField` in `form.slint` is the only text input. Typing goes into `draft`, which only reaches the bound `text` while it passes the field's rules (`numeric`, `whole`, `positive`, `optional`, or `valid` worked out by the owner from `draft`) and resets to `text` when focus leaves. An invalid value never reaches the model, and a field recreated mid-edit shows the last good value. Disabled fields dim their colors instead of using `opacity`, which draws through a layer and shifts the text. The other files are one part of the window each: title bar, control bar, seek bar, volume control, tracks menu, playlist panel, recorder panel, settings dialog, status overlay (buffering, seeking, connection lost), start screen (empty window and drop overlay), load screen (checking and opening), failure screen, audio view, end overlay, link box.
- Anything that isn't a picture (every phase but playing, and audio without cover art) puts a `Theme.backdrop` rectangle over the video area, because mpv's buffer still holds the last frame of the previous file. Only the bars around a playing video stay black. For audio with cover art, Rust renders mpv into the square from `cover-x`, `cover-y` and `cover-size` on `AppWindow` instead of the whole video area, clears the window around it to `Theme.backdrop` (exported to Rust for this) and sets mpv's `background-color` to it while the cover shows. The video stays hidden until `tracks-known` (this file's track list has been read, reset on `StartFile`), and the square is used as soon as the tracks say so, not only once playing, so the cover never shows at full size first. Switching between the square and the video area resizes the buffer without the settle delay. Going straight from one audio file to the next (`StartFile` while playing or opening audio) keeps `audio-only`, `has-cover` and the tags, so the audio view stays up, and Rust stops rendering mpv while opening or until `tracks-known`, so the old cover stays until the new file's frame replaces it (before playback starts mpv may have no frame and renders black). `apply_tracks` ignores the empty track list mpv reports mid-switch, which otherwise ended the audio view. The load screen only covers it once the open gets slow. Going idle or failing resets them (`forget_audio_view`), so a later file never starts with an old cover.
- Loading indicators use `Delayed` from `components/progress.slint`, which fades in after 250 ms. Spinners are only created while shown, since `animation-tick` keeps the window redrawing. The playlist and recorder share the right side, opening one closes the other. The settings dialog sits over the video area.

## Deliberate choices that look odd

Rendering and the UI thread:
- Video redraws go through `request_video_redraw`, which calls winit's `request_redraw` directly. Slint's own `request_redraw` waits on a timer that never fires inside the Windows move/resize loop, which froze playback while a window edge was held.
- mpv renders into its own renderbuffer sized to the video area, and that buffer is only resized once the area size stops changing (`RESIZE_SETTLE_DELAY`). Rendering mpv at each new size stalls the UI thread for about 36 ms per new video frame, which made resizing choppy. Until then the old frame is stretched into the new area, but only its picture part (margins from mpv's `osd-dimensions`, used only while they match the buffer size). Stretching the whole buffer with mpv's black bars kept the picture at its old size when the window grew mostly in one direction.
- mpv runs with `video-timing-offset=0`. Otherwise the render call blocks the UI thread for up to 50 ms waiting for a frame's display time.
- Everything the UI thread does blocks the picture, because Slint presents frames from that thread. Keep slow work off it.

Talking to mpv:
- Commands use `mpv_command_async`. Failures arrive later as `Event::CommandFailed`, without saying which command failed.
- The track list and playlist are read on background threads (`read_in_background`), because each property read waits on mpv's core. A counter drops results from older reads.
- A file is only loaded after the render context exists (in `RenderingSetup`). mpv disables video for a file loaded before that.
- Stream callbacks in `http_cache.rs` must never call libmpv, that deadlocks.

Streaming:
- http(s) URLs are rewritten to `rpcache://<url>` and read by `http_cache.rs`. Turning on a subtitle or audio track makes mpv drop its buffered data and re-read the last second or so (a refresh seek in `demux.c`, no option turns it off). The byte cache serves that re-read from memory instead of the network.
- Jumps use `Range: bytes=X-` and only count when the reply is `206` with a `Content-Range` starting at X. Servers without range support are read forward instead.
- The cache holds 512 MiB by default (a setting) in 1 MiB chunks, evicts the oldest downloaded chunk first, and only keeps the most recently opened URL.
- `cache=yes` is set because mpv does not treat a custom protocol as network, so it would only read 1 s ahead.
- The loaded bands on the seek bar combine two sources. mpv's `demuxer-cache-state` `seekable-ranges` are exact time ranges, observed as an mpv node so reading them never blocks. mpv drops old ranges once its own limit fills, while our byte cache still holds that data, so cached byte ranges are added too. `src/buffered.rs` places them on the timeline by recording (byte read position, mpv `cache-end`) pairs while reading and interpolating between nearby pairs. Dividing bytes by file size was tried first and drifted away from the playback position after a seek.

Window and UI:
- The window is frameless (`no-frame`). Moving and resizing go through winit's `drag_window` and `drag_resize_window`. `drag_resize_window` is not supported on macOS.
- Slint is pinned to `~1.19` because the `unstable-winit-030` feature is outside Slint's stability promise.
- Resume is ours, not mpv's (`src/resume.rs`, mpv's `resume-playback` is off). Entries go to `resume.conf` next to `settings.conf`: one line per file with the key (absolute path, lowercase on Windows, or the full URL), the time it was last written, and `name=value` pairs. It saves the options listed in mpv's own `watch-later-options` that changed since the file loaded, plus `start`, except `volume` and `pause` (also skipped when applying older entries). Opening a file sets `pause` to `no`, so it plays even if the last one was paused. Saved values are applied as file-local options in the `on_load` hook, and the file is saved in the `on_unload` hook, which covers every switch. It also saves every 10 s while playing, on pause, after a seek and on close, so a crash loses at most 10 s. Entries older than the "Forget positions after" setting (3 days by default) are dropped. Videos and audio each have their own option (`resume`, `resume-audio`, the second off by default), and a kind whose option is off is neither saved nor restored. At save time audio means no video track or only cover art (`current-tracks/video/albumart`), and such entries get a bare `audio` field. While loading, the tracks aren't known yet, so that mark or an audio extension decides.
- Fullscreen state is read back from the window on every size change, because the window can leave fullscreen without going through `toggle_fullscreen`.
- On Windows the window is subclassed (`fill_monitor_when_fullscreen`) to answer `WM_NCCALCSIZE` with the full monitor while fullscreen. winit clamps a maximized frameless window to the work area even in fullscreen (winit#4756, open), which left the taskbar strip when going fullscreen from maximized. Fullscreen is told apart by the missing `WS_CAPTION`, which winit removes only then. Un-maximizing first, the usual workaround, made the window visibly shrink and grow again.
- Slint keeps only one `on_winit_window_event` callback per window, and setting another replaces it. The one hook lives in `wire_window_controls` and calls the other handlers (`opener::drop_handler`). A second hook elsewhere silently broke drag and drop in 0.1.0.
- Clicks on a `TouchArea` never take focus in Slint, so Rust hooks winit's mouse presses (`on_winit_window_event`) and calls `release-text-focus` on `AppWindow` before Slint handles the press. Any click takes focus from a text field, and a click on a field then focuses that field. It does nothing while the window's key handler has focus, while a shortcut is being captured, or while the pointer is on the focused field (`Panels.pointer-on-focused-field`), so clicking inside a field doesn't drop and regain focus.
- A single click on the video does not pause. Telling it apart from the first half of a double-click needs a delay, and pausing right away made every double-click into fullscreen stutter. Pausing is done with Space or the play button.
- Slint row layouts put smaller items at the top of the row. Center them with `VerticalLayout { alignment: center; }` or give every item in the row the same height.
- Some names clash with properties every element or `Window` already has: `maximized`, `close`, `color` on `Rectangle`, `max-height`. Pick other names.

## Releases

- `cargo xtask bump <version>` sets the version in `Cargo.toml` (the only place it lives, the app shows `CARGO_PKG_VERSION`) and turns the Unreleased section of `CHANGELOG.md` into a dated one. Commit, then push a `v<version>` tag.
- `cargo xtask package` builds in release mode and runs `cargo-packager` with a config it writes to `target/packager.toml`: an NSIS installer on Windows (per user, with `libmpv-2.dll` and the `rona.ico` that `build.rs` puts next to the exe), an AppImage on Linux (bundling the build machine's `libmpv.so.2` and what it needs). The config is generated so the version stays in `Cargo.toml` and each platform gets only what exists there.
- The NSIS installer registers Rona as a player through `preinstall-section`, with a `RegisterPlayer` section and an uninstaller `un.UnregisterPlayer` section generated by `player_registration` in `xtask/src/package.rs`. Per extension it writes a `Rona.<ext>` ProgID (app icon, quoted open command), a value under `.<ext>\OpenWithProgids`, and `SupportedTypes` under `Applications\rona.exe`, plus `Software\Clients\Media\Rona\Capabilities` and `RegisteredApplications` for Default apps. It never changes an extension's default, and the uninstaller only deletes our own keys and values, never a shared `.<ext>` key. cargo-packager's `file-associations` isn't used: it overwrites each extension's default, leaves the exe path unquoted in the command and its uninstall loop reads the wrong field, so it never removes anything. The extensions come from `src/extensions.rs`, which xtask compiles in with `#[path]`.
- The tag runs `.github/workflows/release.yml`: `check` matches the tag against `Cargo.toml`, `build` packages on windows-latest and ubuntu-24.04 (the oldest Ubuntu whose libmpv is `libmpv.so.2`, and the AppImage needs this glibc or newer) and runs the AppImage with `--version`, which also starts mpv, to catch missing libraries. `deploy` runs `cargo xtask deploy`: it signs each file with minisign, uploads to the `rona-files` B2 bucket (served at `rona.won.fyi`) under `installer/<version>/`, creates the GitHub release with the changelog section as notes, uploads `rona_latest_<suffix>` copies, and writes `updater/latest.json` last. Alongside, `nix` builds the flake's package on x86_64 and aarch64 Linux and pushes it to the niks3 cache at `niks3.kirsi.dev` (the push may fail without failing the job). Then `stable` moves to the tag, which needs both `deploy` and `nix`. A manual run builds and publishes nothing apart from that cache push.
- Update signatures use our own minisign key, not Authenticode, so SmartScreen still warns on first install. `cargo xtask keygen <password>` writes `assets/update-key.pub` and prints the secret key. The domain and bucket are constants in `xtask/src/deploy.rs` and `src/updater.rs`.
- Repo secrets: `RONA_SIGN_KEY`, `RONA_SIGN_PASSWORD`, `B2_APPLICATION_KEY_ID`, `B2_APPLICATION_KEY`.

## Known gaps

- macOS has no package and no libmpv source yet. The mpv release only ships Windows libmpv, and the AppImage bundles Ubuntu's.
- On macOS, edge resizing of the frameless window needs a different approach.
