# rona

A video player with mpv as the playback backend and Slint for the UI, written in Rust. Licensed GPL-3.0-or-later. Only Windows has been tested so far. Linux and macOS are planned.

## Build and run

- libmpv is not built from source. On Windows, `node scripts/tasks.mts fetch-mpv` downloads `libmpv-v0.42.0-x86_64-w64-mingw32-gpl.zip` from the mpv v0.42.0 GitHub release, checks it against the SHA-256 pinned in `scripts/lib/mpv.mts` and extracts it with Windows' own `tar.exe` to `vendor/mpv/windows-x86_64/`. `vendor/` is gitignored. `build.rs` copies `libmpv-2.dll` next to the exe. On Linux, libmpv comes from the system (`libmpv-dev`).
- `cargo run -- [file paths or http(s) URLs]`. Without an argument the window opens empty. `--version` prints the version, starts mpv to check libmpv loads, and exits. `--new-instance` skips single instance, so a `cargo run` while Rona is open starts its own window instead of handing the files to the open one.
- Judge performance with `cargo run --release`. Debug builds make Slint's text code slow, for example the first open of the tracks menu stalls for about 600 ms in debug and not in release.
- `assets/icon.svg` is the only source for the app icon. The title bar uses `assets/title-icon.svg` instead, a bare play triangle, since the dark tile vanishes on the title bar at 16 px. `build.rs` renders it with `resvg` to raw RGBA at 32 and 256 px for the window and taskbar icon (set through winit in `set_window_icons`). On Windows it also builds a multi-size `.ico` with the `image` crate and embeds it in the exe with `winresource`, which needs the Windows SDK's resource compiler. On Linux it writes `share/applications/rona.desktop` and `share/icons/hicolor/<size>/apps/rona.png` (plus the SVG under `scalable`) next to the binary, laid out so installing is copying `share` into `~/.local` or `/usr`. The window's Wayland app id and X11 class are `rona` to match.
- libmpv is loaded at runtime with `libloading`, so there is no link step. The headers in `vendor/mpv/windows-x86_64/include/mpv/` are the reference for every constant and struct in `src/mpv.rs`.

## Layout

- `src/main.rs`: wiring between mpv and the UI, mpv event handling, UI callbacks, window controls, OSD, download speed polling.
- `src/mpv.rs`: hand-written bindings for the client API, the OpenGL render API and the stream callback API.
- `src/video.rs`: `VideoLayer`. mpv renders into an offscreen buffer, which is copied into the video area every frame. The buffer depends on the Renderer setting, which is only read at startup because switching means rebuilding mpv's video output: a Direct3D 11 texture shared with OpenGL (Windows, `src/video_d3d11.rs`, falls back to OpenGL if unavailable) or an OpenGL renderbuffer. mpv's Vulkan support (`vo=gpu-next`, `gpu-api=vulkan`) belongs to its own video output, which the render API replaces, so it isn't offered here.
- `src/http_cache.rs`: the `rpcache://` protocol that http(s) URLs go through, with a byte cache. A read that fails mid-stream reconnects at once, then after 3, 6 and every 12 s, and only shows the connection banner while playback is buffering. Most failures are the server closing a connection left idle while mpv's buffer was full, so they never show. Every GET goes through `request`, which adds the headers a playlist file gave that link (`add_headers`, cleared when anything new opens).
- `src/instance.rs`: single instance. The first launch claims a named pipe (`\\.\pipe\rona-<session id>`, created with `FILE_FLAG_FIRST_PIPE_INSTANCE`) on Windows, or `flock`s a lock file and binds a Unix socket in `XDG_RUNTIME_DIR` elsewhere. Both are atomic and released when the process dies, so two launches at once can't both win and a crash leaves nothing stale. Later launches send a length-prefixed message (the Wayland activation token, then the sources, NUL separated, relative paths already made absolute) and exit only once the window replies that its UI thread took it. A hidden window (closing) or no reply within 10 s makes that launch run as its own window, as does any failure to claim or connect. Each connection gets its own thread (and on Windows a fresh pipe instance), so a stuck sender blocks nobody. On Windows the sender calls `AllowSetForegroundWindow` for the running window, since only the process the user just started may take the foreground. winit's `focus_window` does nothing on Wayland, so `src/wayland.rs` calls `xdg_activation_v1.activate` with the sender's `XDG_ACTIVATION_TOKEN` on the window's own connection. The window opens what arrives within 150 ms of the last launch (`opener::queue_arguments`) as one playlist, because Explorer can start one process per selected file. `--new-instance` and `RP_CAPTURE` runs skip all of this. The design follows Tauri's single-instance plugin, except that Tauri's macOS version removes and rebinds its socket without a lock, which can leave two primaries.
- `src/audio_info.rs`: reads local audio files' tags, cover and bit depth with `lofty` on a background thread, before mpv opens them, so the audio view switches to a file all at once. The playlist read queues the current file, the next 3 and the previous one, and a starting file that isn't cached yet jumps the queue. It reads the same keys the view took from mpv's metadata, and looks for the cover names mpv's `cover-art-auto` uses when there's no embedded one. Covers (JPEG, PNG, WebP) are scaled to at most 640 px and kept decoded for the last 24 files. Behind those full reads, a summary of every playlist entry is read and kept for all of them: the title (mpv only knows a file's title once it has played it), the artist and a cover of at most 72 px for the playlist's rows. Summary reads locate the cover first and decode it once per source (a hash of the embedded picture, or the cover file's path), so an album's tracks share one decode and one buffer. The playlist is read again after each full read, every 25 summaries and when the summary queue runs empty. Rows of audio files show the cover and artist, with an empty tile while a cover is still being read and a note tile for files without one or links. This is decided per row (by extension), so a mixed playlist shows them too, and its video rows get a video tile to keep the column lined up. Playlists with no audio file have no cover column. A pre-read cover is drawn by Slint (`has-cover-image`, `cover-image`) with rounded corners; mpv's own cover rendering is the fallback for files `lofty` can't read, and stays square. Each pre-read cover is also shrunk to 12 px (`ambient-image`), which the audio view stretches over its whole area and darkens, since Slint has no blur. That background only shows behind a Slint-drawn cover, as it would hide one mpv draws underneath. Files without artist and album get their type and size as the album line. While a file opens, mpv's title and tags aren't applied (mpv empties them mid-switch); without pre-read info the view switches to mpv's when playback starts.
- `src/logging.rs`: the log. `debug!`, `info!`, `warn!` and `error!` format the line with its time on the calling thread and hand it to a writer thread, so logging never waits on the disk. One file per day (`rona-YYYY-MM-DD.log`) in `%LOCALAPPDATA%\rona\logs`, `~/.local/state/rona/logs` or `~/Library/Logs/rona`, opened for appending since a second launch writes to the same file. Files older than 7 days are deleted when a day's file opens. Warnings and errors also go to stderr, as does everything before `init` or when the folder can't be used. mpv's own messages come in at its `v` level through `mpv_request_log_messages` and are logged as `mpv/<module>`. Every `Mpv::command` is logged, and failures name the command, since each gets its own reply id. Streams in `http_cache.rs` are numbered (`stream #3`), because mpv can still hold the previous file's stream while opening the next. Panics are logged through a panic hook, and `main` flushes the log before exiting.
- `src/media.rs`: what counts as playable. Link parsing, the video and audio extension lists, the Content-Type list that rules a link out, and byte signatures for the first 4 KiB. No UI.
- `src/playlist_file.rs`: the `.rl` playlist format, JSON with `version`, `type` (series, music, other), top-level info, `playback` defaults, `headers`, `entries` and `sections` (each with entries or an `include` of another `.rl`, up to 4 deep, loops refused). serde structs with a flattened `extra` map at every level, so keys other tools write survive a save. Reading makes every path absolute against the file's folder, or the URL for a playlist from a link, where local paths are dropped. Writing makes paths inside the target folder relative again, with forward slashes. Whole seconds are written as integers. Also M3U export and time text (`1:20`, `1:02:03`). `src/images.rs` loads covers and thumbnails from files or links on one background thread, cropped to fixed boxes and cached.
- `src/opener.rs`: every way a file or link gets opened (command line, file dialog, link box, Ctrl+V, drag and drop), the link check before mpv sees a link without a media extension, and the failure screens. A path or link ending in `.rl`, or an argument whose text starts with `{` (the whole playlist JSON, made absolute against the launching process's folder in `absolute_argument` before any hand-over), is read in the background. One playlist on its own keeps its file (`playlist::Document`), anything mixed opens as a plain list. Every entry that isn't `disabled` is loaded, missing ones too so they show, and `playback.start` is loaded first with the others inserted around it, so mpv never starts entry 1. An open that would replace an edited playlist waits on the save prompt (`held`). "Add files" and "Add link" append to the open list. `Player.phase` (idle, checking, opening, playing, failed) is set here and in `drain_events`. While something plays, a failed open only shows an OSD message.
- `src/settings.rs`: the settings. `Config` is loaded from `settings.conf` (plain `name = value` lines) in the user config folder (`%APPDATA%\rona` on Windows), written back on every change, and applied to mpv as `set` commands after startup, so an option this mpv build doesn't know only logs a failed command. Only properties whose value changed are sent again. The Slint `Settings` global holds what the dialog shows, and its `changed` callback makes Rust read it all back.
- `src/theme.rs`: theme profiles (Settings > Theme). The values in `ui/theme.slint` are the default theme, read at startup before anything is overridden, so "Default" is not a stored profile and can't be edited or deleted. Each profile is `themes/<name>.conf` in the config folder, `name = value` lines holding only the values that differ from the default, so a property added to `theme.slint` later shows its default in every profile. The chosen profile is `theme` in `settings.conf`, empty for the default. Slint globals can't be looked up by name, so every `Theme` property is listed in the `keys!` table there, and a new one needs a line in it. Values are colors (saved as `#rrggbb` or `#rrggbbaa`), lengths in px and durations in ms. A new profile copies the one shown, profile names are file names, and "Reset this page" reverts the whole profile. A changed value is written 400 ms after the last change, since dragging in the color picker changes it many times a second, and any write still waiting is done before switching, renaming or closing.
- `src/color.rs`: reading and writing color text, behind the Slint `ColorText` global. It takes hex with or without `#` (3, 4, 6 or 8 digits) and CSS `rgb()`, `rgba()`, `hsl()`, `hsla()`, `hsv()` and `hsb()` in comma or space syntax with `/ alpha`, and writes `#rrggbb`, or `#rrggbbaa` when not opaque.
- `src/playlist.rs`: the playlist's two orders, shuffle and repeat, editing and undo. mpv's playlist is always the play order, so mpv still does next, previous, gapless playback and `loop-playlist`. The list as shown is Rona's own order of mpv entry `id`s, matched up on every read of mpv's playlist, and is only changed by the user. Without shuffle both orders are the same and moves go to mpv too. With shuffle, Rona rearranges only mpv's playlist: the current entry first and the rest at random when shuffle turns on, a new playlist opens or a repeat starts over, and later additions at a random place after the current one. Entries before the current one in mpv's order show as played. Shuffle doesn't use mpv's own shuffling, which would reorder the list. Repeat is off, once (`loop-playlist=2`, counted from when it's set and kept as "once" for the next playlist) or forever. Shuffle and repeat are kept apart for audio and video playlists in `state.conf`, a playlist counting as audio when every entry has an audio extension, decided in `opener` when it opens. Removing an entry can be undone (message in the panel, or Ctrl+Z) back to its place in the list. mpv gives it a new id, so the re-added entry is matched by file name. Undo history ends when a new playlist opens. Clicking an entry in shuffle first moves it right after the current one in mpv's order, so it counts as played.
  Every list entry has a `Meta`: its playlist file entry (paths absolute), section, merged headers, missing or changed state and the duration seen while playing. Loaded metas wait in `pending` and are matched to mpv ids by file name as mpv lists them, placed by load order. Undo, mirrors and relinking (`replace`, `loadfile ... insert-at` then `playlist-remove`) carry the meta through `restoring`, since mpv gives the entry a new id. The `on_load` hook sets the entry's `start`, `end`, `alang`, `slang`, `volume-gain` and `force-media-title` before resume adds its own options, so a saved position wins over the entry's start. The `on_preloaded` hook adds its subtitles and extra audio (`sub-add`, `audio-add`). Skip ranges are checked on every position update, each once per file. A file playlist's `shuffle` and `repeat` win over the remembered ones when it opens. The panel's rows are entries and section headings (`Row`, with `top` worked out here since headings are 30 px and entries 46 px). A drop lands at the row's list place and joins the section of the row above it. Saving (`build_file`) writes the list order grouped by section, skips included entries (their section keeps its `include`), puts disabled entries back, records `duration` and `check` (size and mtime) for local files, and writes through a temporary file. With `playback.autosave` it saves 1 s after a change.
- `src/playlist_edit.rs` and `ui/playlist-dialogs.slint`: Save, Save as, the save prompt before an open or a close replaces edited changes, Export as M3U, Show file in folder, Find file (which then relinks other missing entries from the same folder), and the playlist and entry details dialogs. Dialog fields bind straight to the `PlaylistDoc` global and its row models (`text <=> item.field`), and are read back on Save. Alt+F4 now goes through `WindowControls.close` too (`on_close_requested`), so the prompt and the usual saves run.
- `src/state.rs`: what Rona remembers on its own rather than what the user chooses: the two volume levels, shuffle and repeat for audio and video playlists, and the window's place and size. It lives in `state.conf` next to `settings.conf`, in the same `name = value` format, so `settings.conf` is only written when a setting changes and can be a read-only file managed by something else. Versions up to 0.1.1 kept these values in `settings.conf`, so that file is read first and `state.conf` wins.
- `src/chapter_skip.rs`: skipping chapters whose titles contain one of the user's names as whole words (Playback settings, empty by default). It reads its settings from the Slint `Settings` global, because `drain_events` runs in a `Send` closure that can't hold `SharedConfig`. It also checks on position updates, since the chapter list is read in the background and can arrive after the chapter is known. Each chapter is checked once per file, so going back to one plays it.
- `src/updater.rs`: checking for and installing updates (Settings > Updates, and a check 5 s after startup unless turned off). It reads `updater/latest.json`, verifies the download with `minisign-verify` against `assets/update-key.pub` (compiled in) before saving it, and only hands it over after the window has closed through the normal close path, so the resume position and settings are saved first: on Windows it starts the NSIS installer with `/P /R`, on Linux it renames the new AppImage over the running one and starts it. Self-update is off in debug builds, without the `self-update` feature, with an empty key file, and on Linux outside an AppImage; the page then points to the download site. `RONA_UPDATE_ENDPOINT` points it at a test manifest and allows installing from a debug build. `cargo-packager-updater` was not used because it exits the process itself when the installer starts, skipping our saves, and brings a second HTTP client.
- `scripts/`: release tooling in TypeScript, run as `node scripts/tasks.mts <command>` and never shipped (see Releases). Node 24 runs the `.mts` files as they are by stripping their types, so there is no compile step and no npm install in CI. That means only erasable TypeScript (no enums, namespaces or parameter properties) and imports with their `.mts` extension. It uses no packages: `fetch`, `node:crypto` and the system's `tar`. `package.json` and `tsconfig.json` are only there for the editor and `npm run typecheck`. Tests use `node:test` (`npm test`).
- `src/recorder_window.rs` and `ui/recorder-window.slint`: the recorder as its own window, the default ("Recorder opens as" in Interface settings, `recorder = window | sidebar`). Both places use `RecorderPanel`. Slint gives every top-level component its own globals, so the window has its own `Recorder`, `Theme`, `Panels` and `WindowControls`. `recorder.rs` writes its status to both `Recorder` globals and reads the form from the window while it's open, and the editable fields are copied over when the window opens and back when it closes. `theme::mirror_to` gives the window every theme value the main window gets. `Panels.recorder-open` in the main window stays the one switch: `app.slint` shows the sidebar or calls `recorder-window-changed`, and the window's close button, Escape and Alt+F4 clear that flag. The window is 320 px wide and exactly as tall as the form (`needed-height` on `RecorderPanel`, set as its min and max height), so it grows and shrinks as fields show and can't be resized by hand. It is created hidden at startup, opens right of the main window the first time (or inside its right edge when the screen ends there) and where it was closed after that, and is hidden when the main window closes, since the event loop runs while any window is shown. On Windows it's owned by the main window (`GWLP_HWNDPARENT`), so it stays above it, minimizes with it and has no taskbar button. Keys there go to the player's shortcuts.
- `src/volume.rs`: the last volume set in the player, kept as `video-volume` and `audio-volume` in `state.conf`. The level for the file's kind is set in the `on_load` hook, so it applies before any sound. The file name decides the kind there, and it's corrected at playback start when the tracks say otherwise. Changes are saved 1 s after the last one, and on close. Resume leaves `volume` out of what it saves per file, so it can't override this.
- `src/shortcuts.rs`: the rebindable keys. The window's key handler passes every key to `Player.key-pressed`, which looks it up here. Letters are stored lowercase so Shift doesn't change the match. Shift with the seek keys uses the long seek step.
- `src/recorder.rs`: recording. In copy mode Start and Stop only remember playback positions, and that range is then written losslessly in the source's container. Matroska and WebM sources go through `src/mkv_cut.rs` on a background thread. Other sources use mpv's `dump-cache`, one part at a time, with `demuxer-max-back-bytes` raised while recording so the range is still buffered. `dump-cache` can't do Matroska: mpv's mkv demuxer gives no decode timestamps, so ffmpeg's muxer rejects every B-frame and the file comes out full of blocks.
- `src/mkv_cut.rs`: copies a time range out of a Matroska file by its own EBML reading and writing. It reads the source directly (local files) or through `http_cache::LinkReader` (links, served from the byte cache and downloading what's missing, without moving the player's read head or connection banner). It starts at the last keyframe at or before Start, found from the Cues (or, without them, by walking the cluster headers). Leading frames decoded after that keyframe but shown before it are dropped. At the end it keeps every frame decoded before the last one shown before Stop, and marks the ones shown after Stop invisible. Subtitle lines already on screen at a part's start are repeated there, shortened, which needs the index's `CueDuration`. Splits start each part at the first keyframe after the boundary, and audio interleaved just after that keyframe still goes to the previous part. Each part keeps the EBML header, Tracks and Attachments (subtitle fonts) as they are, rebuilds Info without the source's UIDs and Duration, writes its own SeekHead, clusters (one per keyframe) and Cues, and patches sizes and the duration at the end. Chapters and Tags are left out. The time on the file's timeline is mpv's position plus `demuxer-start-time`. `stream-record` is not used because it starts at mpv's read-ahead point, which can be minutes past what is on screen. Re-encode mode encodes in a second, hidden mpv instance in encoding mode (`o`, `ovc`, `oac`, `start`), which mpv only finishes writing when that instance is destroyed. With "Encode during playback" off it starts at Stop with `end` set, otherwise it starts at Start and runs behind playback: it pauses once its `time-pos` reaches the playback position and resumes 2 s behind it. At Stop it gets `end` (with a `stop` command as backup once it reaches it) and unpauses. If a seek back left it more than 0.25 s past Stop, it's paused and a new instance encodes the exact range to `<name>.part.<ext>`, which replaces the first file once both are destroyed. Rate control goes into `ovcopts`, per encoder family (`video_options`): software Variable is `crf`, Average is `b`, Constant sets `b`, `minrate`, `maxrate` and `bufsize` to one value (plus `strict-cbr` for x265), and Constrained is `crf` with `maxrate`. NVENC uses `rc` with `cq`, AMF `rc=cqp` with `qp_*`, QSV `global_quality` (ffmpeg's qsvenc picks ICQ, CBR or QVBR from which of `global_quality`, `b` and `maxrate` are set). AMF has no Constrained: its quality modes take no bitrate cap, and QVBR needs pre-analysis and its scale isn't documented. mpv's encoding mode has no two-pass. `src/encoders.rs` finds the hardware encoders the first time the recorder opens, on a background thread: each one encodes 0.4 s of `av://lavfi:color` in its own mpv instance and counts if the file isn't empty and mpv logged no error. libx264 is checked first, so a broken check offers no hardware rather than missing it silently. An empty bitrate uses the source's, and without one known it falls back to `crf`. Opus gets `vbr` on, off or constrained to match, and ffmpeg's AAC encoder is left at its bitrate since its VBR mode is experimental.
- `ui/app.slint`: root window. `ui/state.slint` holds the globals (`Player`, `WindowControls`, `Panels`) and the structs passed from Rust. Rust reaches the UI through `app.global::<Player>()` and friends, not through window properties.
- `ui/theme.slint` has colors, bar heights and the shared transition timings, as the default theme. Its properties are `in-out` so `src/theme.rs` can override them. Every hover, press and focus change animates (`animate background`, `border-color` and so on) with `Theme.hover-duration`, and every popup, menu and dialog fades in and out with `Theme.fade-duration`. A dialog behind an `if` is kept while a fade value is above 0 (`link-fade`, `settings-fade` in `app.slint`), since an `if` alone destroys it at once. `ui/components/` has small shared pieces, with our own form controls in `form.slint` because Slint's standard widgets look different per platform. `ColorField` there is the full color picker (a swatch opening a saturation and brightness square with hue and alpha sliders, next to a field that takes pasted colors in any format `src/color.rs` reads, converted when focus leaves). `ColorChoice` only picks from a fixed row of swatches. Anything clickable uses `Clickable` from `clickable.slint` (a `TouchArea` with the pointer cursor) instead of a bare `TouchArea`, which stays only for backdrops, hover detection and resize edges.
- `TextField` in `form.slint` is the only text input. Typing goes into `draft`, which only reaches the bound `text` while it passes the field's rules (`numeric`, `whole`, `positive`, `optional`, or `valid` worked out by the owner from `draft`) and resets to `text` when focus leaves. An invalid value never reaches the model, and a field recreated mid-edit shows the last good value. Disabled fields dim their colors instead of using `opacity`, which draws through a layer and shifts the text. The other files are one part of the window each: title bar, control bar, seek bar, volume control, tracks menu, playlist panel, recorder panel, settings dialog, status overlay (buffering, seeking, connection lost), start screen (empty window and drop overlay), load screen (checking and opening), failure screen, audio view, end overlay, link box.
- Anything that isn't a picture (every phase but playing, and audio without cover art) puts a `Theme.backdrop` rectangle over the video area, because mpv's buffer still holds the last frame of the previous file. Only the bars around a playing video stay black. For audio with cover art, Rust renders mpv into the square from `cover-x`, `cover-y` and `cover-size` on `AppWindow` instead of the whole video area, clears the window around it to `Theme.backdrop` (exported to Rust for this) and sets mpv's `background-color` to it while the cover shows. The video stays hidden until `tracks-known` (this file's track list has been read, reset on `StartFile`), and the square is used as soon as the tracks say so, not only once playing, so the cover never shows at full size first. Switching between the square and the video area resizes the buffer without the settle delay. Going straight from one audio file to the next (`StartFile` while playing or opening audio) keeps `audio-only`, `has-cover` and the tags, so the audio view stays up, and Rust stops rendering mpv while opening or until `tracks-known`, so the old cover stays until the new file's frame replaces it (before playback starts mpv may have no frame and renders black). `apply_tracks` ignores the empty track list mpv reports mid-switch, which otherwise ended the audio view. The load screen only covers it once the open gets slow. Going idle or failing resets them (`forget_audio_view`), so a later file never starts with an old cover.
- The audio view puts the cover beside the details (track number, title, artist, album, format tags, time, and an "Up next" card with shuffle and repeat) when the video area is at least 640 px wide and 1.2 times as wide as tall, and stacks them otherwise. `app.slint` works out the cover square for both, which is also where Rust renders an mpv-drawn cover.- The playlist panel's rows have a grip for dragging. While dragging, the other rows slide inside fixed slots to make room where the row would land, and the slide only animates while dragging, so the reordered list doesn't slide again on drop. The list scrolls when a dragged row is held near an edge. Rows also have a remove button and a right-click menu. Clicking or right-clicking a row selects it and gives the list keyboard focus: Up and Down move the selection, Delete removes, Enter plays, Escape hands focus back, other keys go to the player's shortcuts.
- Loading indicators use `Delayed` from `components/progress.slint`, which fades in after 250 ms. Spinners are only created while shown, since `animation-tick` keeps the window redrawing. The playlist and a sidebar recorder share the right side, opening one closes the other. The settings dialog sits over the video area.

## Deliberate choices that look odd

Rendering and the UI thread:
- Video redraws go through `request_video_redraw`, which calls winit's `request_redraw` directly. Slint's own `request_redraw` waits on a timer that never fires inside the Windows move/resize loop, which froze playback while a window edge was held.
- mpv renders into its own renderbuffer sized to the video area, and that buffer is only resized once the area size stops changing (`RESIZE_SETTLE_DELAY`). Rendering mpv at each new size stalls the UI thread for about 36 ms per new video frame, which made resizing choppy. Until then the old frame is stretched into the new area, but only its picture part (margins from mpv's `osd-dimensions`, used only while they match the buffer size). Stretching the whole buffer with mpv's black bars kept the picture at its old size when the window grew mostly in one direction.
- A side panel narrows the video area, and mpv puts text subtitles in any black bars. So `without_panel_bars` in `main.rs` makes the area mpv renders into shorter, keeping only the bars the video has at the window's full width (from `video-out-params` `dw`, `dh` and `rotate`). Toggling `sub-use-margins` instead would also pull a wide film's subtitles out of its own bars.
- mpv runs with `video-timing-offset=0`. Otherwise the render call blocks the UI thread for up to 50 ms waiting for a frame's display time.
- Everything the UI thread does blocks the picture, because Slint presents frames from that thread. Keep slow work off it.

Talking to mpv:
- Commands use `mpv_command_async`. Failures arrive later as `Event::CommandFailed`. `Mpv::command` gives each command its own reply id (high bit set, apart from the ids passed to `command_with_id`) and keeps its arguments until the reply, so the failure names the command.
- The track list and playlist are read on background threads (`read_in_background`), because each property read waits on mpv's core. A counter drops results from older reads.
- A file is only loaded after the render context exists (in `RenderingSetup`). mpv disables video for a file loaded before that.
- Stream callbacks in `http_cache.rs` must never call libmpv, that deadlocks.

Streaming:
- http(s) URLs are rewritten to `rpcache://<url>` and read by `http_cache.rs`. Turning on a subtitle or audio track makes mpv drop its buffered data and re-read the last second or so (a refresh seek in `demux.c`, no option turns it off). The byte cache serves that re-read from memory instead of the network.
- Jumps use `Range: bytes=X-` and only count when the reply is `206` with a `Content-Range` starting at X. Servers without range support are read forward instead.
- The cache holds 512 MiB by default (a setting) in 1 MiB chunks, evicts the oldest downloaded chunk first, and only keeps the most recently opened URL.
- `cache=yes` is set because mpv does not treat a custom protocol as network, so it would only read 1 s ahead.
- The loaded bands on the seek bar combine two sources. mpv's `demuxer-cache-state` `seekable-ranges` are exact time ranges, observed as an mpv node so reading them never blocks. mpv drops old ranges once its own limit fills, while our byte cache still holds that data, so cached byte ranges are added too. `src/buffered.rs` places them on the timeline by recording (byte read position, mpv `cache-end`) pairs while reading and interpolating between nearby pairs. Dividing bytes by file size was tried first and drifted away from the playback position after a seek.

Window and UI:
- The window is frameless (`no-frame`). Moving and resizing go through winit's `drag_window` and `drag_resize_window`. `drag_resize_window` is not supported on macOS.
- Slint is pinned to `~1.19` because the `unstable-winit-030` feature is outside Slint's stability promise.
- Resume is ours, not mpv's (`src/resume.rs`, mpv's `resume-playback` is off). Entries go to `resume.conf` next to `settings.conf`: one line per file with the key (absolute path, lowercase on Windows, or the full URL), the time it was last written, and `name=value` pairs. It saves the options listed in mpv's own `watch-later-options` that changed since the file loaded, plus `start`, except `volume` and `pause` (also skipped when applying older entries). Opening a file sets `pause` to `no`, so it plays even if the last one was paused. Saved values are applied as file-local options in the `on_load` hook, and the file is saved in the `on_unload` hook, which covers every switch. It also saves every 10 s while playing, on pause, after a seek and on close, so a crash loses at most 10 s. Entries older than the "Forget positions after" setting (3 days by default) are dropped. Videos and audio each have their own option (`resume`, `resume-audio`, the second off by default), and a kind whose option is off is neither saved nor restored. At save time audio means no video track or only cover art (`current-tracks/video/albumart`), and such entries get a bare `audio` field. While loading, the tracks aren't known yet, so that mark or an audio extension decides.
- Fullscreen state is read back from the window on every size change, because the window can leave fullscreen without going through `toggle_fullscreen`.
- The cursor over the video hides after the "hide controls" delay, in fullscreen always and in a window while a video plays (not paused, not audio). Slint's `mouse-cursor` isn't used for this: Slint only applies a cursor change on the next mouse event, so a timer that flips it never hid a still cursor, and winit hides it with `ShowCursor`, which does nothing while another window has focus. `app.slint` reports `pointer-hidden` (idle and hovering the video) to Rust, and on Windows the window subclass answers `WM_SETCURSOR` with no cursor, sending itself one so the change applies without movement. Elsewhere it uses winit's `set_cursor_visible`.
- On Windows the window is subclassed (`subclass_window`) to answer `WM_NCCALCSIZE` with the full monitor while fullscreen. winit clamps a maximized frameless window to the work area even in fullscreen (winit#4756, open), which left the taskbar strip when going fullscreen from maximized. Fullscreen is told apart by the missing `WS_CAPTION`, which winit removes only then. Un-maximizing first, the usual workaround, made the window visibly shrink and grow again.
- Slint keeps only one `on_winit_window_event` callback per window, and setting another replaces it. The one hook lives in `wire_window_controls` and calls the other handlers (`opener::drop_handler`). A second hook elsewhere silently broke drag and drop in 0.1.0.
- Clicks on a `TouchArea` never take focus in Slint, so Rust hooks winit's mouse presses (`on_winit_window_event`) and calls `release-text-focus` on `AppWindow` before Slint handles the press. Any click takes focus from a text field, and a click on a field then focuses that field. It does nothing while the window's key handler has focus, while a shortcut is being captured, or while the pointer is on the focused field (`Panels.pointer-on-focused-field`), so clicking inside a field doesn't drop and regain focus.
- A single click on the video does not pause. Telling it apart from the first half of a double-click needs a delay, and pausing right away made every double-click into fullscreen stutter. Pausing is done with Space or the play button.
- Slint row layouts put smaller items at the top of the row. Center them with `VerticalLayout { alignment: center; }` or give every item in the row the same height.
- Some names clash with properties every element or `Window` already has: `maximized`, `close`, `color` on `Rectangle`, `max-height`. Pick other names.

## Releases

- `npm run version:bump <version>` (or `node scripts/tasks.mts bump <version>`) sets the version in `Cargo.toml` (the only place it lives, the app shows `CARGO_PKG_VERSION`) and turns the Unreleased section of `CHANGELOG.md` into a dated one. Commit, then push a `v<version>` tag.
- `node scripts/tasks.mts package` builds in release mode and runs `cargo-packager` with a config it writes to `target/packager.toml`: an NSIS installer on Windows (per user, with `libmpv-2.dll` and the `rona.ico` that `build.rs` puts next to the exe), an AppImage on Linux (bundling the build machine's `libmpv.so.2` and what it needs). The config is generated so the version stays in `Cargo.toml` and each platform gets only what exists there.
- The NSIS installer registers Rona as a player through `preinstall-section`, with a `RegisterPlayer` section and an uninstaller `un.UnregisterPlayer` section generated by `playerRegistration` in `scripts/lib/package.mts`. Per extension it writes a `Rona.<ext>` ProgID (app icon, quoted open command), a value under `.<ext>\OpenWithProgids`, and `SupportedTypes` under `Applications\rona.exe`, plus `Software\Clients\Media\Rona\Capabilities` and `RegisteredApplications` for Default apps. It never changes an extension's default, and the uninstaller only deletes our own keys and values, never a shared `.<ext>` key. cargo-packager's `file-associations` isn't used: it overwrites each extension's default, leaves the exe path unquoted in the command and its uninstall loop reads the wrong field, so it never removes anything. The extensions are read out of `src/extensions.rs` by `scripts/lib/extensions.mts`, which fails if a list's count doesn't match its declared length. That includes `PLAYLIST_EXTENSIONS` (`.rl`), registered the same way, and as the one exception Rona is also made its default (`.rl` default value `Rona.rl`), since it's Rona's own format. The uninstaller clears that value only while it still reads `Rona.rl`. On Linux `build.rs` writes `share/mime/packages/rona.xml` defining `application/x-rona-playlist` for `*.rl` (reading the extension list from `src/extensions.rs` with `include!`), and the `.desktop` file lists it. The AppImage gets cargo-packager's own desktop file, so it doesn't carry the type.
- The tag runs `.github/workflows/release.yml`: `check` matches the tag against `Cargo.toml`, `build` packages on windows-latest and ubuntu-24.04 (the oldest Ubuntu whose libmpv is `libmpv.so.2`, and the AppImage needs this glibc or newer) and runs the AppImage with `--version`, which also starts mpv, to catch missing libraries. `deploy` runs `node scripts/tasks.mts deploy`: it signs each file with minisign (checking each signature against `assets/update-key.pub` before anything is uploaded), uploads to the `rona-files` B2 bucket (served at `rona.won.fyi`) under `installer/<version>/`, creates the GitHub release with the changelog section as notes, uploads `rona_latest_<suffix>` copies, and writes `updater/latest.json` last. Alongside, `nix` builds the flake's package on x86_64 and aarch64 Linux and pushes it to the niks3 cache at `niks3.kirsi.dev` (the push may fail without failing the job). Then `stable` moves to the tag, which needs both `deploy` and `nix`. A manual run builds and publishes nothing apart from that cache push.
- Update signatures use our own minisign key, not Authenticode, so SmartScreen still warns on first install. `node scripts/tasks.mts keygen <password>` writes `assets/update-key.pub` and prints the secret key. Node has no minisign, so `scripts/lib/minisign.mts` implements it with `node:crypto`: prehashed Ed25519 signatures ("ED"), and secret keys XORed with scrypt output, whose N, r and p come from the key's stored opslimit and memlimit as libsodium's `pickparams` works them out. That keeps keys made by minisign or the Rust crate readable. The secret key's checksum is BLAKE2b-256, which Node lacks, so `scripts/lib/blake2b.mts` has it. The domain and bucket are constants in `scripts/lib/deploy.mts` and `src/updater.rs`.
- Repo secrets: `RONA_SIGN_KEY`, `RONA_SIGN_PASSWORD`, `B2_APPLICATION_KEY_ID`, `B2_APPLICATION_KEY`.

## Known gaps

- macOS has no package and no libmpv source yet. The mpv release only ships Windows libmpv, and the AppImage bundles Ubuntu's.
- On macOS, edge resizing of the frameless window needs a different approach.
